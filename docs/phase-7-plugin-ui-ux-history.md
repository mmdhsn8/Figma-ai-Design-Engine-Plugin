### Persistence and recovery decisions

- The normal version 1 `fad.chat-history.v1:<document-page>` index, stable conversation IDs, message bounds, ordering rules, and per-chat checkpoint keys remain unchanged. Valid records require no migration.
- When the version 1 index is partially invalid, the loader returns individually validated conversations in stable update order. Invalid, duplicate-ID, and over-cap records plus invalid root metadata are staged in `fad.chat-history-preserved.v1:<document-page>` before a later main-index write. The sidecar is versioned and capped at 2 MiB; if it is malformed or cannot be written, mutation fails closed and the original index/checkpoints remain intact.
- Explicit deletion removes the requested ID from the visible index and matching quarantined entries. Existing running/invalid checkpoint guards and rollback behavior remain. History deletion never calls Figma node APIs.
- Conversation messages, execution checkpoints, and progressive-generation drafts remain in separate existing stores. No prompt, provider payload, token, or corrupt record content is included in the new History integrity notice.
- Storage writes remain serialized by document/page key. Upserts remain ID-idempotent, and stale update timestamps cannot overwrite newer saved conversation data.

### Accessibility and panel checks

- The existing drawer focus trap, Escape behavior, close-focus return, and visible focus styles remain; the More destination is now included in its accessible navigation. History status/error notices use live regions, the list reports result counts, and each entry remains keyboard-operable.
