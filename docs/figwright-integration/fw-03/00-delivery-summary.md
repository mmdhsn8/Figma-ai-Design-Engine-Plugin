# FW-3 — delivery summary

**Status: PARTIAL / LIVE PENDING.** The repository now contains a strict, versioned, non-mutating native batch planner, a default-off build-time planning gate, security/ownership contract tests, a retained-root regression, and a local fake-runtime benchmark. It does **not** dispatch native batches or change the production renderer route. No Figma Desktop file, provider, or model was used.

The implementation seam is intentionally isolated in `src/shared/native-batch.ts`. Inspection found that Universal already sends one `design-program-render` message per screen; Figma main invokes the existing renderer, which batches all node work inside that plugin call. Native mutations are already serialized by the current task owner. A second executor would introduce a second mutation/receipt boundary without reducing the current UI-to-plugin render dispatch count. The typed plan is therefore experimental evidence and contract work, not a claimed speedup.

`VITE_FW3_NATIVE_BATCH=fw3-native-batch-v1` opts the planner in at build time. The default is off. This gate does not enable Figma writes; the current production path and gate-off behavior remain on the existing renderer. Local gate-on output deliberately retains that renderer.

The request is one task, one screen, one existing program fingerprint, one page and one authorized root. `batchId` is the existing render `requestId` for that in-flight transaction, not a new ledger or persistent identity. The actual ChatTask storage revision (`hash` + `bytes`) is not passed from the existing `save`/`renderProgram` seam to this adapter, so the request binds the saved program fingerprint only; this is another reason it is not safe to wire into native mutation yet. It accepts only frame, text, rectangle/ellipse, layout and solid-paint operations. Earlier-create references are validated. Unsupported images, vectors, instances, external/local resource references and FW-2 reuse return an explicit fallback result so the existing renderer can retain authority. The v1 shape contains no delete, reparent, arbitrary code, remote import or cross-page write operation.

The unchanged Universal task remains the only checkpoint owner. The existing plugin renderer creates/reuses task-owned roots, does geometry checks, preserves failed attached roots, registers them in the existing executor, and the UI task owner completes only after native readback. FW-3 did not add Stop/Resume integration; those semantics remain entirely with the current route.

Local fake-runtime comparison: F1/F3/F10 each retained the same modeled render/readback dispatch counts and Figma API operation counts with planning on. Native mutation method counts and tree counts were identical; all replayed root IDs remained stable and no extra nodes appeared. Gate-on candidate serialization adds roughly 7.9/29.4/79.5 KB of *unsent plan payload* and local planner work. The one-run harness times vary and are not Desktop timing. See [benchmark details](02-baseline-and-metrics.md) and [machine-readable output](03-local-benchmark.json).

Desktop/live acceptance, actual bridge-message counts, and any native batch execution/readback receipt remain unverified. Do not treat this delivery as production-ready batching or as authorization for a Desktop A/B run.
