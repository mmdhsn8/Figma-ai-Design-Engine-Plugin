## Local path comparison

The current path is `DesignProgramV1` validation/preflight → per-screen checkpoint save in `src/ui/universal-design-task.ts` → one `design-program-render` post from `src/ui/design-program-bridge.ts` → Figma `main.ts` → `renderDesignProgramLocal` / `renderMultiScreenDesign` → geometry verification and root adoption in the existing `figma-tool-executor.ts` → UI `task-native-inspect` readback → checkpoint verification. The UI task owner serializes screen mutation and owns Stop, late-response fencing, and resume state.

`src/shared/design-program-operations.ts` is an older experimental native-operation planner. It is not reused: the current renderer already coalesces native work per screen, and introducing its operation list as another executor/ledger would bypass or duplicate renderer geometry, root recovery, task adoption and existing ownership. FW-2 resource references keep their existing revalidation and do not enter the FW-3 plan subset.

FW-1 and FW-2 artifacts were read in `docs/figwright-integration/fw-01/` and `fw-02/`. Their live acceptance remains pending. The F1/F3/F10 rubric and fixtures were not modified; FW-3's local benchmark fixture is separate and synthetic.
