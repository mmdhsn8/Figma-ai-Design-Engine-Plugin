# 08 — Recommendation and FW-2 handoff

## Ranked disposition

1. **ADOPT PATTERN — benchmark evidence rule only.** Require a screenshot plus fresh native readback before calling a screen accepted. This targets the measured-in-project risk that structurally valid output may still look sparse or unprofessional. Hypothesis: complete visual review coverage will expose defects that geometry/contrast preflight alone misses. This is a process choice for FW-1 evidence collection, not a production code port.
2. **ALREADY HAVE EQUIVALENT — no renderer replacement.** The current path already validates typed programs, checkpoints per screen, bounds retries, tracks native transaction identity, and verifies the committed native tree. Figwright's atomic batch pattern does not justify replacing this state/ownership flow.
3. **DEFER — bounded screenshot-guided correction and/or a narrow batch experiment.** Consider only after authorized live F1 and F3 runs show a specific visual reject or excess native dispatch burden. Test hypothesis: reduce unresolved visual defects or native/MCP dispatches per completed screen without increasing duplicate roots, rollback residue, unexpected deletes, or unrelated mutations. Require at least three reasonably comparable successful F1/F3 runs per variant before a performance claim.
4. **REJECT — arbitrary code execution, destructive broad RPCs, and a second checkpoint ledger.** These increase execution and ownership risk without measured benefit and conflict with the current typed DesignProgram/native renderer boundary.

## FW-2 entry gate

FW-1 provides source-level candidates only. No benefit is demonstrated in live comparable evidence, so do not start a production port. If the live gates pass, FW-2 should be limited to one proof-driven experiment: compare screenshot-guided review/correction on matched F1/F3 runs, with exact native readback and bounded correction count. Add a batch-dispatch comparison only if traces show native dispatch overhead is a measured bottleneck.

Before any code transfer, require:

- repeatable live evidence and human visual scores;
- the same authorized model/provider or an explicitly separated system-level comparison;
- a specific reduction in an observed failure/quality/dispatch measure with no safety regression;
- full MIT notice retention and third-party dependency license/security review;
- no second writer, no global MCP configuration, and no parallel checkpoint ledger;
- a rollback plan that preserves Universal Engine as the default and leaves Legacy optional.

No FW-2 production source change is authorized or made by this report.
