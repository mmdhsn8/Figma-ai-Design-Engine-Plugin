# Contract and boundaries

`DesignContextSnapshotSchema` (`schemaVersion: 1`, `feature: "fw2-context-v1"`) is canonical. Records are ordered by bounded root/child order; resources are sorted by host ID. The Figma page ID and, if exposed, `figma.fileKey` identify the source. The existing page-scoped document ID is a routing guard, not a Figma file ID. Timestamp is wall time; `ctx1-*` is a deterministic metadata fingerprint, not a server revision or permission token. The provider sees the projection without the file key or resource keys.

- **Scope:** explicit create grounding phrase + selected roots/subtree or current page; merely placing on the current page is not consent to read it. Edit grounding requires the single selected root to match the already verified edit node and page; the existing target/ownership checks still control writes. No arbitrary IDs, page loading, library imports, or whole-document node scans by FW-2. Selection uses the host state at read start. Ordinary conversational messages never execute this path.
- **Data:** geometry, hierarchy, visibility/clipping, common Auto Layout and text alignment/font metadata, IDs for observed resource links and approved local definitions. No raw names, text, notes, credentials, comments, screenshots or images. A few generic resource roles are allowlisted hints inferred from labels, not identities. RTL is a script hint, not a bidi analysis. Selected instances are not expanded. Selection and page reads limit styles/variables to those actually referenced; an additional phrase such as “include the file-local design system” in a page request allows a sample of file-local **definitions**, whose Figma listing APIs have no pagination. This never enumerates other pages' nodes.
- **Bounds:** 16 roots, 40 visited nodes, depth 5, 24 resources, 900 ms read budget, 8 KiB wire cap with a stricter 3,072-byte conservative token proxy; 56 KiB existing Chat input envelope and existing Companion body/record limits. The 3,072 proxy is not a measured provider tokenizer budget. Lists, strings and enums are checked at host/UI/Companion boundaries. `coverage`, fixed reason codes, and `omitted` describe the captured sample; omitted is a lower bound, not an exhaustive count of every unvisited descendant.
- **Freshness:** host plugin session, request/task/document/page/selection and digest must still agree; grants expire after five minutes and never persist. Stop, reload, selection/page changes or stale lookups prevent further contextual reuse; late responses cannot replace the active request. A missing read uses the existing path. An attached root is never removed or replaced because reuse or readback failed. Resuming a saved plan does not recapture an earlier planning snapshot.
- **Precedence:** brief choices within mandatory accessibility/safety checks; pinned Brand Kit unless explicitly overridden; compatible authorized native context; project defaults. Existing Brand Kit pinning still runs. If local candidates disagree with final color/geometry, they cannot win at dispatch. The planner receives conflict guidance; the renderer reports stale, ambiguous or inactive reuse without private labels.

The supported native write subset is intentionally narrow: fixed, content-free components (including a distinct supported variant), exact visual equivalence, and unambiguous, opaque sRGB-like single fills using a local paint style or a directly resolved single-mode COLOR variable. Text/effect/grid styles and other variables are discovery metadata only. No component properties/overrides, contentful button/card/nav masters, remote imports, multi-mode bindings, document-wide searches, or edit-time substitutions. Already adopted work and original DesignProgram/task fingerprints remain unchanged by the feature; no new checkpoint schema or ledger.
