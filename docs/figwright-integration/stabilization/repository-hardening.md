# Universal Engine repository hardening

## A. Executive findings

The Chat task owner now reads back saved, previously verified roots on Resume. If Figma cannot verify one of those roots, the owner can no longer complete the task on the strength of the old checkpoint. Healthy roots keep their IDs and verification history. The same task owner still plans, checkpoints and commits screens in page order.

Companion accepts delayed same-session model catalog results across credential rotation and keeps terminal SSE results and read deadlines independent of upstream cleanup. Checkpoint request identity now follows the destination storage slot. Source builds derive their identity from actual filesystem inputs, including exported checkouts and Unicode paths. Explicit zero and oversized screen counts reach the existing range check, and screenshot counts no longer supply a screen count.

The confirmed findings below are reproducible locally. Remaining hypotheses concern real Desktop timing, visual fidelity, synchronization with user edits, and provider behavior. No live document or provider was used. The existing [stabilization README](README.md) describes the earlier pass.
