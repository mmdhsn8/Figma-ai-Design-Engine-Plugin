# Phase 5.8.1 — architectural stability refactor

## Scope and evidence boundary

This is the Phase 5.8.1 architectural audit/refactor, not a new phase or isolated sizing hotfix. It preserves the existing task lifecycle, canonical Zod tool contracts, task-scoped refs, native operation ledger, persisted 32-mutation segments, acknowledgement reconciliation, structural QA, timeout diagnostics, and export controls while centralizing native compatibility decisions and closing the remaining deterministic text-sizing and recovery gaps. It does not replace sign-in/model selection or add a paid API or Expo dependency.

The latest reported FILL error is **proven in source**: `src/plugin/figma-tool-executor.ts` resolved the requested parent, then threw `FILL text sizing requires an Auto Layout frame or component parent.` whenever a `create_text` action requested FILL under PAGE or a non-Auto-Layout FRAME/COMPONENT. This happened before `api.createText()`. The generic mutation error handler then classified this known pre-native rejection as ambiguous. The historical diagnostic did not retain the original arguments or actual parent, so the old live call cannot be reconstructed exactly. The executor integration fixture below reproduces the source branch with explicit test arguments and records the actual node and parent types; it is not claimed as a replay of the unavailable live payload.

## Current call path and ownership

```text
src/ui/App.tsx
  sendChatMessage / Resume / Stop
    -> src/ui/chat-task.ts: runChatTask, durable plan/stage/operation ledger
      -> src/ui/companion-client.ts: authorized SSE request
        -> src/companion/server.ts: lifecycle-valid tools + Responses call validation
          -> src/shared/chat-tools.ts: generated JSON schema + strict argument parse
      -> UI execute adapter (tool-execute)
        -> src/plugin/main.ts: UIToPluginSchema and dispatch
          -> src/plugin/figma-tool-executor.ts: executeBatch / executeOperation
            -> resolveTaskAction: task alias -> canonical page-scoped ref
            -> persisted idempotency record (intent before native dispatch)
            -> actionResult: current native identity/parent preflight
              -> src/plugin/figma-compatibility.ts: compatibility preflight, normalization, and parenting decisions
              -> Figma native mutation / read
            -> native acknowledgement + saved operation result
      -> task ledger reconciliation -> required-ref/native QA -> UI progress
```

`src/shared/figma-tools.ts` owns the runtime action and protocol schemas. `src/shared/chat-tools.ts` generates model-facing tool parameter schemas from those runtime Zod action schemas (planning and stage completion have their own canonical Zod schemas). `src/ui/chat-task.ts` owns model lifecycle, stage/task budgets, durable segments, and mutation accounting; the plugin executor owns native identity, parent state, operation idempotency, and native acknowledgement. Figma Desktop is the authority for actual native acceptance; automated mocks do not substitute for it.

## Compatibility policy added for text sizing

`src/plugin/figma-compatibility.ts` is the single policy owner for supported native parents/targets, text and Auto Layout sizing normalization, property/style capabilities, explicit parenting decisions, and delete-consent validity. The executor supplies current native facts (resolved node, local style availability, consent state); the policy module decides compatibility before the mutation boundary. `normalizeTextSizingForParent` still runs after resolving the actual parent again following font loading and before text creation, attachment, or any `layoutSizing*` setter. The executor marks the native mutation boundary explicitly: deterministic preflight failures are `rejected`; only errors after that boundary can be `ambiguous`.

| Actual parent snapshot              | Requested sizing                                       | Deterministic behavior                                                                                                                                                 |
| ----------------------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PAGE / NONE`                       | FILL                                                   | Normalize FILL to FIXED at the explicitly requested width/height. A page has no bounded content box to fill.                                                           |
| `FRAME` or `COMPONENT / NONE`       | FILL                                                   | Normalize FILL to FIXED at the live parent width/height. Reject dimensions outside the executor's documented 1–20,000 px range with a safe field path and remediation. |
| `FRAME` or `COMPONENT / HORIZONTAL  | VERTICAL`                                              | FILL/HUG                                                                                                                                                               | Keep native sizing and set `layoutSizingHorizontal/Vertical` only after attachment to that verified Auto Layout parent. |
| `PAGE` or non-Auto-Layout container | HUG/HUG or FIXED/HUG                                   | Map to native `WIDTH_AND_HEIGHT` or `HEIGHT` text auto-resize, respectively, and report the normalization.                                                             |
| `PAGE` or non-Auto-Layout container | HUG width with FIXED/FILL height, or HUG/FILL conflict | Reject before node creation with `text_sizing_requires_auto_layout`; do not silently choose an axis or force Auto Layout.                                              |
| Detached/stale parent ref           | Any sizing                                             | Existing page/node identity checks reject before creating a text node.                                                                                                 |

Every successful normalization includes only tool/node type, safe field path, requested/applied mode, parent type/layout mode when relevant, reason, resolved dimension, or affected refs. It contains no text, node name, raw arguments, or prompt. Native FILL is never assigned under PAGE or `layoutMode:NONE`. A rejected compatibility check is definitely pre-mutation and therefore is not reported as an ambiguous native commit. Repeated identical structural findings are also compared against confirmed-mutation progress; the runner stops the same finding without progress, while the existing three-check QA ceiling remains for findings after actual mutations.

## Executor state migration

The page-scoped executor record advances from schema version 1 to 2 so successful sizing-normalization traces survive operation replay/status reads. `loadState` accepts both versions and upgrades v1 in memory without dropping refs, fingerprints, operation IDs, or prior results; the next durable save writes v2. `downgradeStoredToolStateForRollback` removes only v2 compatibility diagnostics and returns the v1 shape, making the metadata migration reversible. No canvas nodes or chat checkpoints are cleared. Old completed entries without normalization data remain valid and are not retroactively guessed.

Chat task checkpoints remain their existing schema/version. Their ledger records the operation result independently. Other native protections, page scope, ownership/fingerprints, deletion consent, state/result byte bounds, operation limits, and segment accounting remain in place.

## Failure classification and recovery boundaries

| Condition                                                      | Classification                                                                                         | Safe next action                                                                                      |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| Safe FILL/HUG representation issue                             | Local normalization, then normal native acknowledgement                                                | Continue; inspect the sanitized normalization trace if geometry is unexpected.                        |
| Sizing intent cannot be represented outside Auto Layout        | `rejected` with `compatibilityFailure` (`fieldPath`, actual parent type/layout, permitted remediation) | Use fixed size or explicitly establish Auto Layout before creating the text.                          |
| Stale/ambiguous canonical ref or detached parent               | `rejected` reference-resolution result                                                                 | Inspect the exact current node/selection; do not recreate or guess.                                   |
| Explicit cross-parent append                                   | `rejected`; no move                                                                                    | Use `reparent_node` only when the requested design intent authorizes that move.                       |
| Native call may have applied but acknowledgement/save was lost | `ambiguous`                                                                                            | Reconcile actual node ID/parent before retry; never replay confirmed work blindly.                    |
| Earlier batch operation failed/cancelled                       | Remaining entries `not_attempted`                                                                      | Resume from the next unacknowledged operation.                                                        |
| SSE EOF/interruption/timeout/user Stop                         | Existing typed transport/cancellation outcome                                                          | Resume persisted task from its last acknowledged operation; no automatic replay of confirmed entries. |

The wider planning, alias, capacity, partial-batch, transport, QA, and diagnostic-export evidence and root-cause limits remain in [phase-5-8-stability-gate.md](phase-5-8-stability-gate.md) and [stability-gate-root-cause.md](stability-gate-root-cause.md). Existing arbitrary 32-operation-per-stage stops were replaced there with persisted 32-mutation segments; current resource ceilings remain explicit and preserve work when reached.

## Follow-up: structural QA measurement and repair verification

`parseResponsesFunctionCalls` labels the >10-function-call validation error `call_set/too_many_calls`; `call_set` is not a tool. The authenticated Responses request uses the runtime-derived lifecycle allowlist and validation occurs before an SSE `tool_calls` event. The model guidance now states the ten-call response limit, and an unsupported `type: "call_set"` wrapper is rejected without inspecting embedded calls. The exact live raw response remains unavailable.

The stage verifier already performed a fresh native `inspect_nodes` operation rather than reading checkpoint geometry. It did round local and absolute measurements to integer pixels, omit transforms/layout metadata and compare clipped rectangles without parent-local transform handling. Contrast diagnostics rounded a full-precision threshold decision to two decimals, while native paint alpha was omitted. Native summaries now preserve unrounded measured bounds, absolute transforms, layout sizing/alignment/padding, text alignment, and child sizing/positioning. The QA compares transformed child corners in the parent's local space and reports overflow/layout context. Intentional clipping cannot always be inferred from geometry; ambiguous cases fail closed and are not automatically unclipped or moved.

Inspection tree assembly had another confirmed gap: when a request named both a parent and its child, deduplication returned the child as a separate root and omitted it from the parent's child list. `inspect_nodes` now attaches the existing summary under the parent without recounting the node, so structural QA retains native ancestry.

For supported single-solid paints, foreground/background alpha and effective node opacity are composited before contrast comparison. The threshold uses full precision and the diagnostic preserves the unrounded ratio and configured threshold. Unsupported stacked/gradient paint combinations are left unmeasured instead of guessed.

Native solid-paint RGB floats are preserved alongside the existing hex fields and used by the audit to avoid false threshold flips caused by 8-bit quantization. A boundary regression exercises a color whose native channels pass 4.5:1 while its rounded hex value does not.

Each confirmed mutation during structural repair now schedules a durable, fresh native inspection before any further model repair. The ledger/checkpoint retains before/after measurements, affected canonical rule/ref identities, the repair operation ID, progress and resolved count. Repair rounds accept only one native mutation at a time. Unchanged/worse measurements stop the path; Resume performs a fresh local QA probe and allows further model correction only if native measurements changed. This does not increase existing QA/retry budgets or alter partial-commit/idempotency behavior.

## Regression evidence

`tests/figma-tool-executor.test.ts` executes real production runner/executor code against a Figma-shaped mock that throws if `FILL` is set when the current parent is not a FRAME/COMPONENT with Auto Layout. Coverage includes:

- Page-root FILL → explicit fixed geometry; non-Auto-Layout frame FILL → parent content size.
- Native FILL under Auto Layout FRAME and COMPONENT.
- HUG text auto-resize mapping; incompatible HUG/FILL rejection before node creation.
- Stale/detached parent rejection, and a parent changing from `NONE` to Auto Layout while font loading is pending.
- A task-runner → `UIToPluginSchema` adapter → actual executor path for root FILL; stage QA completes and counts one mutation.
- Persisted normalization trace in operation status; v1→v2 migration, downgrade, and no-duplicate reload.

Historical baseline: 365/366 tests passed, with one 100-screen draft test timeout under concurrent load; an isolated rerun passed 7/7. Final audit verification, `npm test -- --testTimeout=60000 --reporter=dot`, passed **373 tests across 27 files**. The executor suite includes a post-mutation lost-acknowledgement regression that reloads the same operation, reconciles the original node by operation/ref/fingerprint/type/parent, and asserts that its native ID and node count do not change. Additional compatibility regressions confirm unsupported target/parent/property and missing-local-style failures are rejected before writes. Identical structural findings without a new confirmed mutation now terminate the correction loop. This is simulated runner/protocol/executor evidence, not authenticated Desktop acceptance.

Latest follow-up verification passes **387 tests across 27 files**, typechecks, companion compilation, lint, formatting, build, `verify:phase5`, and `git diff --check`. It additionally tests that Figma-native float RGB survives executor inspection and prevents contrast misclassification from 8-bit hex rounding. Automated mock evidence still does not satisfy the authenticated Desktop gate.

## Remaining risks and acceptance

- Figma Desktop's actual font/Auto Layout setter behavior, Persian shaping, visual appearance, clipboard sandbox, screenshot, and timing are not evidenced by the mock suite.
- When an unconstrained page-root text asks for FILL, the safe fallback is the authored fixed size, not an unbounded attempt to fill the canvas.
- Native HUG/FILL combinations that cannot be represented by text auto-resize without changing axis meaning fail closed and require explicit Auto Layout intent.
- The automated design and recovery fixtures are bounded synthetic cases; they do not establish visual quality, live model reliability, performance on large real documents, or compatibility across Figma Desktop versions.
