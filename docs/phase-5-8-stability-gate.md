# Phase 5.8 stability gate — not production acceptance

This note covers the separate planning-metadata rejection. The persisted reference-alias collision and its evidence boundary are documented in [stability-gate-root-cause.md](stability-gate-root-cause.md).

## Latest failure: root cause

The reported rejection is now reproducible: `plan_canvas_task` received `completed`, `operations`, `rounds`, and `verification` in a stage. The plan input schema was strict, so `unrecognized_keys` was correct.

The application encouraged this mistake: `chatTaskInput` serialized internal runtime stages into assistant checkpoint summaries, and successful planning/stage-completion tool outputs returned those same runtime stages. Those stages looked like reusable planning examples, despite the tool schema accepting only title, goal, logical refs, and completion criteria. `verification` is not part of the current runtime schema either; the exact upstream reasoning/payload is unavailable, so its provenance is not proven.

The old loops fed planning failures back to the model without a repeated-error/no-progress check. A valid plan already existed in some paths but could still be requested again. Counting tests did not cover this production transport/continuation interaction. The reported ten rounds versus the source's four pre-plan/eight per-stage limits also cannot establish which compiled plugin/companion revision ran; reload/rebuild evidence is required.

## Minimal changes

- Canonical planning contract is `ChatPlanActionSchema`, version 1 (`planVersion` defaults to 1 for existing callers). The model-facing tool derives from it. Checkpoint model summaries and tool outputs project stages to planning fields only, with execution position kept separately.
- Only known runtime stage metadata is deterministically removed at the argument boundary. It cannot authorize commits, set completion, or alter verification. The strict plan schema then runs as before; unknown design/styling properties are not dropped. A safe `planning_runtime_metadata_ignored` diagnostic and tool-result notice disclose this handling.
- A saved plan is never replaced by a repeated plan call. The model is directed to the next unfinished stage. A repeated replan without progress stops rather than consuming the whole stage budget.
- Persistent error signatures omit call IDs and compare confirmed canvas commits/completed stages. Repeated identical validation errors stop after one targeted correction; existing total limits still apply to differing errors. Reference failures use the same no-progress protection. Retry does not reset these guards.
- Checkpoints expose failure category, safe code, committed count, and operation ID where available. Categories distinguish model schema, planning, executor validation, native runtime, rate limit, timeout, partial commit and ambiguous recovery. Some legacy executor failures remain classified from bounded error text because they do not yet carry a typed cause; they are not proof that a failed write had no effect.

### Diagnostic export and structural QA observability

The chat panel's copy action previously depended only on `navigator.clipboard.writeText`, which may be unavailable or denied inside Figma Desktop's sandboxed plugin UI; rejection had no clipboard fallback. Copy now tries the Clipboard API then a temporary selected textarea with `document.execCommand("copy")`. **Download diagnostic JSON** uses a Blob URL and anchor, independent of clipboard permissions. Both actions report visible success/failure in the chat activity region.

Structural verification previously retained only the QA attempt count and finding count; the final `no_progress_repeated_error` did not identify the exact failing rule. Checkpoints and sanitized exports now preserve allowlisted rule codes, affected logical refs, expected/actual bounded metrics, each verification attempt, and confirmed repair-operation count. Finding messages, node names/text, prompt, model responses, and credentials are not included in the exported JSON. Clipboard and download helpers, privacy filtering, three-check failure history, and confirmed repair accounting have automated regressions. Figma Desktop clipboard/download behavior remains unverified here.

### Follow-up: live structural-QA and Responses call-set failure

The live report records 22 confirmed mutations, 18 logical nodes, five read-only operations, three QA attempts, two repair operations, 21 model requests, 15 native batches, 0/2 stages, three clipping findings, and two contrast findings. It also reports `model_schema/tool_arguments_invalid` and `call_set/too_many_calls`. The raw Responses payload, exact failed node geometry/color samples and running build IDs were not provided.

**Confirmed source interpretation:** `call_set` is the error-stage label generated by `parseResponsesFunctionCalls`, not a callable tool. In this source, `too_many_calls` is emitted when one completed Responses output has more than ten `function_call` items. The companion rejects the whole response before dispatch, so no call from the rejected set is executed. The exact names/count and whether an additional unsupported wrapper was present cannot be recovered without the sanitized validation issue from a rebuilt run. Explicit `type: "call_set"` wrappers are now separately rejected; embedded content is not parsed or executed. The upstream request continues to allow parallel tool calls, but instructions now state the ten-call response limit.

**Confirmed measurement/repair gaps:** QA already issues a new native `inspect_nodes` operation for each completion attempt; it does not source geometry from a saved checkpoint or reuse the model-inspection cache. However `summarizeNode` rounded geometry to whole pixels and omitted transforms and Auto Layout context. Clipping compared those boxes directly. Contrast was compared at full precision but reported at two decimals, and alpha was not composited. Repair accounting counted successful native setters as executed repairs without checking whether they cleared or measurably improved the finding; verification only occurred at the next completion request.

An additional source-confirmed inspection issue was found: when both a logical parent and child were requested, `inspect_nodes` returned the child as a separate root and omitted it from the parent's `children` because it had already been marked seen. That could prevent parent-relative QA on a multi-ref stage. The executor now reuses the existing child summary when assembling the parent tree while retaining the unique-node cap. Whether the live three clipping reports had this ancestry shape is unknown without the raw sanitized refs/tree.

**Change:** native inspection now preserves fractional local/absolute bounds and transforms, padding, Auto Layout sizing/alignment, text alignment, child layout sizing and positioning. Clipping comparisons use the parent-local transform when available and report measured overflow plus layout context. Since native geometry cannot prove whether a crop is intended, the runner does not automatically unclip, move, resize, delete, or recreate a layer. Contrast is calculated after supported solid-paint alpha compositing, against the full-precision threshold; diagnostics expose unrounded ratio/threshold. Each confirmed structural repair is followed by a new, durable native inspection; the checkpoint records before/after findings linked to the repair operation and resolved count. A mutation response during QA repair is restricted to one native mutation so a later call cannot rely on stale findings. If measurements do not improve, automatic repair stops; Resume performs a fresh local probe and only reopens model correction if the native measurements changed. Retry budgets and execution safety limits are unchanged.

Contrast inspection now also preserves Figma's native floating-point RGB channels beside the 8-bit hex compatibility fields and uses the floats for the threshold calculation. Regression coverage demonstrates a native color that passes 4.5:1 although its rounded `#8B6F7D` value falls just below it; contrast is therefore not based on lossy hex quantization when native channels are available.

Regression coverage now includes the exact five-finding shape, a sub-4.5 value that rounds to 4.50, 3.61 contrast, translucent-paint compositing, nested transformed RTL Auto Layout, clipped/unclipped cases, unchanged repair termination, actual native-executor geometry repair/reinspection, oversized call sets and unsupported wrappers, exact 22-mutation reload/Resume, and existing Home/Product plus existing purchase-button-only edits. These are tests of production runner/executor code against mocked Figma objects, not authenticated Desktop acceptance.

Remaining risks: exact live call/wrapper data and the two repairs' effects remain unknown; intentional clipping cannot always be inferred; paint stacks other than one solid color remain unmeasured rather than guessed; mock layout is not Figma Desktop's Persian font shaping or final rendering. Do not treat automated verification as production readiness.
